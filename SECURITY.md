# Security

## Threat model

skillwharf writes into directories that coding agents read as instructions (`.claude/skills`, `.agents/skills`, `.cursor/skills`). A skill is therefore code-equivalent: installing one is like installing a dependency. The tool's job is to make sure that what lands there is exactly what you asked for, and nothing else.

## What skillwharf does

- **Validates every path component.** Skill names, git hosts and ports, repository paths, GitHub owners/repos, git refs and repo sub-paths are checked against strict patterns before use, including values read back from `skillwharf.json` and `skillwharf.lock.json` (which teammates may edit by hand). A host is a lowercase DNS name, an IPv4 address or a bracketed IPv6 address (private ranges are allowed: company servers live there) with an optional port. Each folder name in a sub-path or repository path may use only letters, digits, `.`, `_` and `-`, none may be `..` or end in `.`; in a sub-path no folder may be called `.git` (any letter case; `x.git` is fine), and in a repository path no component may be `.git` or end in `.git` except that the last one may carry the `.git` suffix, because paths are echoed in copy-paste commands and some file systems drop a trailing dot. Leading and trailing whitespace of a source is trimmed; a git source (not a local `path:`) that contains whitespace inside, `?`, `#`, `%` or a backslash is refused. A ref that is all hex and not exactly 40 characters (7 to 39 or 41 to 64) is refused, because git reads it as a ref name that a repository's owner can create; a commit pin is the full 40 characters, and a tag or branch with such a name is written `@refs/tags/<name>` or `@refs/heads/<name>` (fetched by its full ref, never taken for a commit). The agent folders are the known agent directories `.claude`, `.agents` and `.cursor` (the folders the adapters in `src/agents.ts` use). An `agentPaths` override must sit at least one level inside one of them (for example `.claude/custom`), every folder name must match `[A-Za-z0-9._-]+`, none may end in `.`, be `..`, or be `.git` or `.skillwharf` (compared after Unicode folding), and control and bidirectional-override characters are refused. Names that another file system would alias (`GIT~1`, trailing dots, ignorable code points) cannot be written with that charset. An override anywhere else, such as `node_modules`, `scripts` or `.husky`, is rejected, and there is no flag to relax it. A manifest that would write outside the store or the agent folders is rejected.
- **Never writes through a symlink inside the project.** Before any copy, write, link or delete in the store, an agent folder, the manifest or the lockfile, skillwharf checks every existing path component below the project root (the home directory for `--global`) and refuses if one is a symlink or resolves outside that root. A repository that commits `.skillwharf/skills` or `.claude` as a link cannot redirect writes elsewhere. The project root itself may be reached through a symlink.
- **Checks the lockfile against the manifest.** A lock entry's `resolved` must name the same protocol, host, port, repository path and sub-path as the manifest source (host compared lowercased, paths as written), at a full 40-character commit, and the clone URL must be the same too (the `.git` suffix and the ssh user count), or the same local path; the commit is fetched from the manifest's own spelling of the URL, never the lock's. `sync` checks every entry that has to be fetched this way before it makes any git call for any skill, so one mismatching entry stops the whole run with nothing fetched (`update` re-pins from the manifest and has no lock check). Anything else is refused, and the error names `skillwharf update <name> --source <new>` for a repository that moved.
- **Never passes user input as a git option.** Refs that start with `-` are refused; git is invoked with `execFile` (no shell), a fixed argument order and `--` before the URL.
- **Limits what git may do.** Every git call runs with `GIT_ALLOW_PROTOCOL=https:ssh`, so a URL that git rewrites to `file:`, `ext:` or `git:` is refused; if you set `GIT_ALLOW_PROTOCOL` yourself it can only narrow that list, never widen it. Sources with another scheme (`git://`, `file:`, `ext::`, a plain `http://` URL) are refused when they are parsed, except that an `http://` web URL of GitHub, GitLab or Bitbucket is converted to its https form (it is never fetched over http); any URL that contains credentials is refused too (they belong in your git credential helper or ssh agent; only the user `git` may be written in an ssh URL). The URL is passed after `--`, so it can never be read as an option. Every call also carries `-c core.hooksPath=` pointing at nothing (your global hooks do not run on a fetched tree), `-c http.followRedirects=false` (an https server cannot send git to another host), empty LFS filter settings with `filter.lfs.required=false` and `GIT_LFS_SKIP_SMUDGE=1` (a repository's `.gitattributes` cannot make checkout call an LFS endpoint), and the variables that select a repository (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_PREFIX`, `GIT_SHALLOW_FILE`, `GIT_GRAFT_FILE`, `GIT_REPLACE_REF_BASE`, `GIT_QUARANTINE_PATH`, `GIT_NO_REPLACE_OBJECTS`) are removed from its environment, so running inside a git hook never points skillwharf's temporary clone at your own repository. `GIT_TERMINAL_PROMPT=0` and a closed standard input mean git itself never prompts at a terminal, and no askpass program can either: `GIT_ASKPASS` is set empty, `SSH_ASKPASS_REQUIRE=never` and `-c core.askPass=` are passed, unless you run the command with `--allow-askpass`. (git tries an askpass program before the terminal prompt, so without this any host a repository, submodule or registry names could raise a credential prompt in an editor's terminal.) An authentication failure is reported with the fix: a git credential helper, or `--allow-askpass`. A clone is made with `--no-checkout`, and before the checkout `.git/info/attributes` is written as `* -filter -ident -text -eol`, which outranks the repository's own `.gitattributes`: no `filter=` driver (a global one of that name included), no `$Id$` expansion and no text or line-ending conversion runs, so files come out as committed; `working-tree-encoding` is not switched off. git runs under a small supervisor process, in a process group (a session, on POSIX) of its own and without your terminal: ssh cannot ask about a host key or a passphrase (connect once with ssh to trust a new host, or use an ssh agent; skillwharf says so when ssh reports a host key problem). A call that runs longer than 120 seconds (`--git-timeout`) is killed together with everything git started, with the URL named; all the calls of one `add`, `sync` or `update` share a limit of four times that (`--git-deadline`), and a search across several registries has one `--git-timeout` for all of them. Ctrl-C reaches the supervisor, which ends git's whole group, and skillwharf removes its temporary clone and exits 130; a SIGTERM to skillwharf alone ends git too (the supervisor notices its parent is gone) but leaves the temporary clone behind. On Windows the supervisor ends the process tree with `taskkill /T /F`; Windows is not covered by CI. skillwharf does not disable certificate or host-key checks, ever, and does not call any host's API. Your `GIT_SSH_COMMAND`, credential helpers, ssh configuration and URL rewrites are not touched.
- **Treats links in a fetched repository by where they point.** A link on the requested sub-path is refused: the sub-path is walked one component at a time and the result must lie inside the clone. Inside the skill folder, a link whose real target is a file or folder inside the fetched repository (outside every `.git` folder, compared without regard to letter case) is copied as that file or folder; a link that leaves the repository, points into `.git`, is broken or points at a special file is dropped and reported on `add`. Links are resolved by hand, as text, before the file system is asked about them: link text that is absolute or UNC (`/etc/x`, `//host/share/x`, `\\host\share`, `C:/x`) is refused outright and never opened (so a repository cannot make this machine reach out to a network share), other text is resolved against the folder the link is in and must stay inside the clone at every hop (at most 32), and only then is the real path asked for. The project's own paths get the same treatment: an agent folder entry is followed by hand, inside the project only, so a chain that reaches an absolute or UNC target at any hop (`x -> ../../evil`, `evil -> //host/share`) is reported as not skillwharf's and never opened; a stored `path:` source naming a network share or a drive (`path://host/share`, `path:\\host\share`, `path:C:/x`, on every platform, the global manifest included) is refused outright, and one in a project is checked for staying inside it (as text, links followed by hand) before the file system is asked about it; a registry location of that kind is refused too, and a relative one in a manifest must stay inside the folder of the manifest that lists it. A folder link that leads back into a folder being copied is a cycle and is refused. Every entry and byte of the resolved content counts against the size cap while it is copied, so links cannot multiply a folder past it. The store never holds a symlink. A `SKILL.md` that is a link counts only when it resolves to a regular file inside the repository, so a repository cannot use one to make skillwharf read a local file. A local `path:` source keeps the old rule: every symlink is dropped.
- **Pins submodules by the parent's commit.** A submodule on the requested sub-path is read from the fetched commit (the gitlink's recorded sha and the committed `.gitmodules`; a symlinked `.gitmodules` is refused), its URL is held to the same grammar and credential rules as a typed source (a relative URL resolves against the parent's), and it is fetched at exactly the recorded commit with the same guards. skillwharf never runs `git submodule`. A submodule's files are placed with the same link rule as any other skill folder (a link inside the submodule is followed, one that leaves it is dropped and reported), under a bound of ten times the skill caps (20,000 entries, 500 MB: only part of a submodule is installed, but a link bomb still hits a limit). Only one level is followed: a submodule that contains another is refused naming the inner repository, as is a source that touches more than 16. A registry that lives in a git repository is only an index: its submodules are never opened.
- **Never replaces files it did not create.** `add` and `sync` refuse to overwrite an existing agent-side folder that skillwharf did not produce; `--force` is required. `add --all` checks every skill (name, store path, agent folders, size) before it writes the first one, and skips, with the reason, a folder whose name cannot be recorded as a valid sub-path. A real folder counts as skillwharf's own copy only when the lockfile records that skillwharf made a copy there (the fallback when a symlink is not permitted; `links` in the lock entry) and the folder is still exactly what copying the store folder produces: the same files byte for byte, the same folders, and no `.git`, symlink or special file anywhere in it. Identical content alone is not proof, since your own copy or clone of a skill is identical too. `remove` only deletes the exact link skillwharf would have written, a symlink resolving to the (non-symlink) store folder, or such a recorded copy; anything else, including your own clone of the same repository, is left in place. The `links` record is lockfile data that a teammate or a pull request can edit, so it is not proof on its own: before `remove` or `sync` deletes or replaces a recorded copy, the folder must also be byte-identical to the store folder, and a folder that is the skill's own source is refused outright (`remove` checks that, as `add`, `sync`, `update` and `doctor` do). A forged record plus a byte-identical folder that is not the skill's source is therefore the one case where a folder skillwharf did not create can be removed or replaced; its content is the same bytes as the store folder, so it survives in the skill's source (or in git, if the store folder is committed), not in the store itself: `remove` deletes the store and the lock entry in the same run, and a forged lockfile can carry a pin that does not exist. Everything else is refused, except a dangling symlink of your own at an agent target, which `add`, `sync` and `update` replace (only the link text is lost; `remove` leaves it). A store entry that is itself a symlink is never treated as installed.
- **Never copies a folder onto itself.** A `path:` source may not be, contain or lie inside the skill store or the skill's own agent folders (after resolving every link); `add`, `sync`, `update` and `doctor` refuse it, naming the folder, and the copy routine itself refuses a destination that overlaps its source. Otherwise `sync` would replace your folder with a link into the store, and `update` or `remove` would then delete the only copy.
- **Does not replace a managed skill from another source.** `add` refuses a skill whose name is already in the manifest with a different source (printing both) unless you pass `--force`; re-adding the same source is allowed.
- **Pins what you got.** The lockfile records the full commit sha and a sha256 over file paths, the owner-executable bit and bytes of the regular files in the store folder. `sync` installs a skill that is missing from the store at exactly that commit; if the host refuses to serve a commit by its hash, it clones the branch or tag the manifest names (the default branch if none) and accepts that only when HEAD is exactly the pinned commit (a manifest that names a commit itself has no fallback). A lockfile written by 0.1.x hashed folders with every link left out, so when the hash of the content with links resolved does not match the pin, `sync` also tries that older rule, which is the stricter of the two, and installs it only if it reproduces the pin exactly. It fetches and checks every missing skill into a temporary folder first, and installs and links them only when all of them pass; so it refuses, with nothing installed and the lockfile unchanged, if any commit cannot be fetched (unless you pass `--allow-unpinned`), if any content's hash differs from the lockfile, or if any lock entry has no `integrity` hash (unless you pass `--allow-unpinned`, which installs the pinned commit unchecked and writes the hash it computed). A foreign folder in an agent directory is a separate refusal that comes after the install: the store and lockfile are then consistent, and the link is what is missing. `update` has the same two-phase shape: it checks every skill's paths, source and agent folders (a foreign folder is refused before any store is replaced), fetches and size-checks all of them into a temporary folder, and only then replaces the stores, saving each lock entry right after its store is replaced and before it links. A skill that has no lock entry yet is installed from its manifest source as it is now and then pinned. `sync` does not re-check a store folder that is already on disk; `doctor` flags local drift, a missing hash (on this machine the folder is installed but unpinned) and symlinks in the store.
- **Treats registries as untrusted data.** Every index, whether it came from https, a git repository or a local path, goes through the same check: entry names are validated, sources must be git sources that pass the source rules (a local path, a `file:` or `git://` URL, a URL with credentials or a bad sub-path is dropped), descriptions are truncated to 300 characters, and only the known fields of an entry are kept. Plain `http://` registries are refused, an https registry URL that contains credentials is refused (nothing is sent), redirects are not followed, and a response over 5 MB is refused. A registry given as a local path, or an `index.json` in a git repository, must be a regular file (not a symlink, FIFO or device) under the same cap. A registry in a git repository is fetched with the same guards as a skill. The name `default` belongs to the public registry: a manifest cannot give it another location. An entry whose source ends in an all-hex ref that is not a full commit sha is left out and reported by name. A registry that fails to load is reported by name and does not hide the others; `publish` refuses to write through a symlinked `index.json`; `add <name>` refuses a name two registries list, and refuses altogether (unless `--from` names a registry) while any configured registry failed to load, since the skill might be listed there too; an interrupt during a registry load ends the command (exit 130) rather than counting as one registry's failure.
- **Sanitises what it prints.** Strings from manifests, lockfiles, registries, SKILL.md files, session logs and file paths are stripped of control characters (C0, C1, DEL) and bidirectional-override characters before they reach the terminal, including the strings in `--json` output.
- **Caps what it installs.** A skill folder with more than 2,000 files and folders or more than 50 MB is refused before anything is copied into the store. `--max-skill-files` and `--max-skill-size` (megabytes) raise the cap. A `SKILL.md` over 1 MB is refused before it is parsed.
- **Bounds the upward search for the project.** The search for `skillwharf.json` goes upward from the working directory. It never finds a manifest in your home directory (it stops there), and it stops before a parent folder that the current user does not own, so a manifest planted in a shared folder such as `/tmp` does not become the project of whoever works below it. That is all it does: when the working directory is not under your home directory, folders above it are not refused, root is exempt from the ownership check, and the working directory itself is not checked at all. When no manifest is found the working directory becomes the project root, so run skillwharf inside the project, not in `~`, `/tmp` or `/`.
- **Sends nothing anywhere.** No telemetry, no accounts. `usage` reads Claude Code's local session logs only. The one-time hint about sources and registries is a local marker file (`~/.skillwharf/hints.json`, written through the same no-symlink check as every other write; if that fails, no hint is shown) and makes no network request. The package has no install-time script (`preinstall`, `install`, `postinstall`, `prepare`); `prepublishOnly` runs only when the maintainer publishes.

## Known limits

- **It does not review a skill's content.** Read a SKILL.md before installing it, as you would a shell script.
- **A compromised upstream at the ref you asked for is faithfully installed.** Pin commits in the lockfile and read `skillwharf update` output before trusting the result.
- **The lock pins a commit and a content hash, not a repository's history.** GitHub can serve commits that belong to a fork of a repository under the upstream's URL, so a commit sha alone does not prove it sits on that repository's own branches. The `integrity` hash is what ties the lock to the files you reviewed.
- **The size cap covers the installed folder, not the clone.** `git clone --depth 1` fetches the whole repository (and a submodule fetch the whole submodule) before the cap is checked on the skill folder inside it.
- **A registry you add is trusted to its schema, not reviewed.** Its entries are checked for shape and for the source rules, not for what the skills they point at contain.
- **Git's own configuration is honoured and is yours to manage.** Credential helpers, ssh configuration (skillwharf runs git without a terminal, so a first connection to an unknown ssh host fails instead of asking; trust the host with ssh once), `url.<base>.insteadOf` rewrites and `GIT_SSH_COMMAND` are used as they are; only the protocol list (https and ssh) and the prompt and timeout settings are skillwharf's. A rewrite to another https or ssh URL is followed (one to any other protocol is refused, see above).
- **A git call can take up to the timeout, a command up to four times that.** 120 seconds per call by default (`--git-timeout`) and 480 seconds for all the git calls of one `add`, `sync` or `update` (`--git-deadline`). A SIGTERM sent to skillwharf alone ends git but leaves the temporary clone in your temp folder.
- **Windows is implemented but not covered by CI.** There is no Windows runner. On Windows git runs in a new hidden console of its own (so it shares nothing with yours), the tree is ended with `%SystemRoot%\System32\taskkill.exe /T /F` (by full path), the supervisor watches its parent with a liveness probe, and symlinks fall back to copies; none of that is tested on Windows.
- **A cancel that reaches only skillwharf's pid cannot clean up.** At a terminal Ctrl-C reaches git's supervisor as well, skillwharf holds the signal, ends git, removes its temporary clone and exits 130. Elsewhere (an editor's or CI's cancel button signals the pid alone) skillwharf ends at once, because a signal handler cannot run while a synchronous git call is in progress; the supervisor notices and ends git, but the temporary clone stays in your temp folder.
- **`--git-timeout` and `--git-deadline` accept at most 2,000,000 seconds** (a longer timer would overflow).
- **A per-URL `http.<url>.followRedirects` in your own git configuration beats the general `http.followRedirects=false` skillwharf passes**, so a redirect you allowed for one server is followed.
- **A 0.1.x lock may have hashed converted bytes.** Files are now checked out exactly as committed. A lock written by 0.1.x on a machine where an LFS smudge filter ran, where the skill's `.gitattributes` asked for `eol=crlf`, `text`, `ident` or a `filter=`, or where `core.autocrlf=true` was set, hashed different bytes; `sync` reports an integrity mismatch for such a skill and (for a lock with no `links` record, as 0.1.x wrote) says to run `skillwharf update <name>`, which re-pins the committed bytes.
- **Encoding conversion is not switched off.** Filter drivers, `$Id$` expansion and text and line-ending conversion are disabled at checkout; `working-tree-encoding`, which git does itself, is not.
- **Moved repositories are not followed.** Redirects are not followed and no host API is asked; a repository that moved is repointed by hand with `skillwharf update <name> --source <new>`.
- **Submodules deeper than one level are refused**, not followed.
- **Copies are not links.** On Windows without Developer Mode, symlinks fall back to copies, recorded in the lockfile. `doctor` reports them; `sync` and `update` refresh a recorded copy, but a copy you edit is treated as a folder skillwharf did not create and is never replaced without `--force`. A copy is recorded only when the skill has a lock entry: a committed store folder with no lock entry is linked without one, and a copy made then is not recorded. Copies made by 0.1.0 or 0.1.1, which did not record them, and a copy whose write failed partway are foreign too: `sync` refuses them without `--force`, `remove` leaves them, and the store folder stays the reference copy.
- **A committed store folder is not re-checked by `sync`.** If you commit `.skillwharf/skills`, `sync` leaves a store folder that is already present alone; only `doctor` compares it with the lockfile.
- **Agent-folder overrides have no escape hatch.** `agentPaths` accepts only subfolders of `.claude`, `.agents` and `.cursor`; a team that wants skills elsewhere cannot configure that in this version. A project that lives directly in the home directory is not found by the upward search.
- **Usage tracking covers Claude Code only.** Codex and Cursor do not write comparable local logs, so a skill that fires only there shows as "never used".
- **Local path sources you type are trusted.** A path given to `skillwharf add` is yours by definition; skillwharf copies whatever is there, with symlinks removed, and does not check it further. A `path:` source read back from a project's manifest or lockfile must resolve inside the project (relative paths resolve against the project root); `sync` and `update` refuse one outside it, on any machine, unless you pass `--allow-outside-paths`. The global manifest in `~/.skillwharf` is yours, so its path sources are not confined.
- **Symlinked agent folders are refused, including in your home directory.** If `~/.claude` or `~/.claude/skills` is a symlink (for example from a dotfiles manager), `--global` installs refuse to write through it.
- **The registry index is a list, not an endorsement.** Entries are schema-checked, not reviewed.

If any statement in this file is not true of the code, treat that as a vulnerability and report it.

## Supported versions

Only the latest published release is supported. Please update before reporting, if you can.

## Reporting

Please do not open a public issue for a vulnerability. Use GitHub's private vulnerability reporting on this repository (**Security → Report a vulnerability**) and include a reproduction. You will get an acknowledgement within a few days and a fix or a reasoned answer as fast as the problem warrants.
